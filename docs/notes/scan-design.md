# 扫描设计

日期：2026-11-19。状态：当前设计；[Hook Detect](../../plugins/si-mcp-skills/skills/hook-detect/) 已有研究预览实现，首版发布仍未验收。决策依据见 [ADR 0001](../adr/0001-python-mcp-skill-and-read-only-boundary.md)和[ADR 0002](../adr/0002-region-first-detection.md)。

## 目标与入口

扫描最小单元是模块。`module` 入口要求显式 PID 和模块名；重名模块必须用基址或模块身份消歧。`process` 入口显式选择全部模块或指定模块集合，复用同一个模块扫描器，共享可审计预算，单个模块失败不阻断其他模块。

进程选择必须显示身份、父进程、启动时间和选择规则。测试中未显式指定 PID 时选择启动时间最早的精确进程名实例；主进程退出后该规则会选中最早已存活的子进程，因此报告必须记录实际 PID、sequence 和选择原因，不使用模糊名称匹配。

模块身份包至少包含 PID、`process_sequence_number`、基址、映射大小、路径、模块类型和可用加载时间。开始扫描前和提交结果前必须复验进程与模块身份；模块卸载、基址重用或路径变化标记目标变化，不写成零差异。

## 配置与 MCP 边界

`ScanConfig` 使用 Pydantic v2 strict 配置，默认至少包含：

| 字段 | 固定含义 |
|---|---|
| `page_size=4096` | PE 头首读提示；不是系统页大小。 |
| `patch_block_size=512` | 连续差异严格小于该值才进入 Capstone 分类。 |
| `max_read_bytes=65535` | 单次进程内存读取硬上限，用户配置不可提高。 |
| RPC/时间/响应/总内存预算 | 预算耗尽输出 `partial`，不自动扩大范围。 |
| 并发上限 | 允许磁盘解析并发；共享 MCP session 的读取串行化。 |

`ph_utils` 只暴露实际需要的工具：进程/模块/页枚举与进程内存读取。工具响应必须以 `structuredContent` 为准，逐项校验 PID、sequence、地址、长度、snapshot freshness、hex 完整性和分页一致性。text JSON 与结构化内容冲突时拒绝或以结构化内容为准并记录冲突。

## PE 基线与可执行区间

1. 读取目标模块内存 PE 头，先验证 `e_lfanew`、可选头、节表和目录声明都在首读/头部预算内；不足时仅在模块映射和预算内续读。
2. 读取磁盘候选 PE。路径、`MZ`、大小、签名或名称各自都不能单独证明基线可信；当前最低配对条件是模块大小、机器位数、映射头一致性和已知重定位归一化。发布前必须补充可复验的文件哈希/版本与替换场景。
3. LIEF 普通解析用于磁盘布局；连续 dump 必须使用 `parse_from_dump` 或等价 RVA 映射，不能把 RVA 布局交给按文件偏移读取的解析器。
4. 候选可比区间是磁盘 raw-backed 可执行节与当前运行时 image executable 页交集。读取按最多 65535 字节分块，跨块合并连续 patch；读取失败或空洞保留覆盖缺口。
5. 普通基址重定位先归一化。未知重定位类型、无重定位证据但基址改变、页保护未知或 guard 页都输出不可比较原因，不补零比较。

## Inline patch 分类

完整 diff 先产生连续 patch：RVA、长度、所在区间和覆盖来源。小于 512 字节的 patch 再用 Capstone 分析：

- patch 首字节解码为完整 `JMP`，且操作数完整落在 patch 内，可分类 direct/memory indirect inline 候选并记录目标。
- 入口附近出现磁盘中不存在的受改写影响的 `RET`，可分类为返回补丁，例如 `SetUnhandledExceptionFilter` 的 `xor eax,eax; ret 4`。
- 只改变既有指令操作数、无法建立可信边界、差异跨块或缺上下文的情形保留 `patch` 或 `unknown`，不冒充 inline。
- 跳转目标只用于归因和后续证据，不跟踪任意地址来补结论；控制转移不等于恶意。

## EAT

先分别确认磁盘与内存导出目录：已验证缺失、存在、未知/损坏。只有两侧都可靠缺失才标记不适用；一侧存在一侧缺失报告目录不一致。

两侧可解析时比较：

- 导出目录字段、 ordinal base、函数数、名称数和三个表 RVA；
- 每个序号槽位的 32 位 RVA；
- 名称到槽位索引的映射；
- 转发字符串与转发目标。

空槽、数据导出和无名导出不按代码入口判断。EAT 差异可以证明表改写，不自动推导 inline 或恶意性。

## IAT

IAT 状态是“实际指针与可信语义预期的比较”，不是 raw diff。流程：

1. 磁盘导入方给出 DLL、名称或序号、IAT RVA、是否 delay import。
2. 按目标模块位数读取进程内 IAT 槽位实际指针。
3. 用目标进程已加载模块的实际基址和磁盘导出建立预期地址；转发链逐级解析，API set 必须使用目标环境的权威映射或可信 schema。
4. delay import 有两个合法冷状态：磁盘/重定位后的未解析 thunk，或已解析为可信导出；其他值报告 mismatch 或 unknown，不因 delay 标签直接放行。
5. 预期导出缺失、名称重复、转发循环、API set 无法解析、依赖文件不可信时输出未知；落在同一个系统 DLL 内不足以证明正确。

当前研究入口允许“全进程唯一同名直接导出”作为临时候选来源，但这不是 API set 权威解析，发布版不能把它当作完整 IAT 覆盖。

## 输出与覆盖

报告按模块/阶段输出：

- inline：可比可执行字节数、读取 gap、patch RVA/长度/分类、跳转目标与归因；
- EAT：目录状态、槽位/名称/转发比较范围；
- IAT：槽位总数、equal、mismatch、delay unresolved、API set unknown、基线 unknown；
- 目标：进程/模块身份、前后复验、预算、工具调用和耗时。

只有列出的已比较范围能写“无发现”。原始 hex、完整业务路径和无关进程信息不进入对话或报告；路径可输出哈希或用户明确要求的可审计形式。
