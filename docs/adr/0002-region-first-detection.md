# ADR 0002：region-first 检测顺序

日期：2026-11-19。状态：已接受。

## 背景

研究阶段曾用命名导出入口窗口定位 inline 候选。WXWork 实测发现相邻导出的 32-byte 窗口重叠时，`WriteFile` 的改写会被错误归因到相邻的 `UnlockFileEx`。用户进一步指出：如果入口前 5 字节未变而 `Entry+N` 才开始 hook，导出入口窗口会漏检。

完整可执行节 diff 实测覆盖 `kernel32.dll` 和 `KernelBase.dll` 共 3,094,491 字节，直接得到三个 5 字节 patch，再由导出 RVA 仅做展示归因；离线样本同时验证了“前 6 字节不变、第 6 字节开始 direct jump”的场景。

## 决策

1. inline patch 发现源是模块内**可信磁盘可执行内容与当前运行时可执行映射的交集**。先完整读取、比较得到连续差异 RVA，再进入分类。
2. 磁盘节标记可执行但运行时失去执行权、运行时新增执行权但没有磁盘可执行对照的区间分别报告权限变化/不可比较，不参与伪装的字节 diff。
3. 连续差异小于 `patch_block_size=512` 时才尝试 Capstone。只有 patch 首字节能解码成完整控制转移、或另有可信指令边界时才标记 inline 候选；仅修改既有 `jmp [mem]` 的操作数字节保持普通 patch。
4. 导入/导出表不能决定 inline 扫描范围。导出 RVA、符号名或模块名只能用于发现后的归因和展示。
5. EAT 是导出目录、槽位 RVA、名称/序号映射和转发字符串的语义比较。
6. IAT 不做磁盘 IAT 与内存 IAT 的 raw diff。先从磁盘导入方取得 DLL、名称/序号和槽位 RVA；再读取目标进程实际指针；最后与可信磁盘导出、目标模块实际基址、已验证转发和 API set 关系得到的预期地址比较。无法建立预期时报告未知。

## 取舍

- region-first 会读取更多字节，预算和覆盖报告成为核心输出；换来的是不依赖符号/导出是否存在，能发现函数中部或无名代码 patch。
- 保守指令边界规则会降低召回，尤其对起点不在新指令边界的改写；这优于把任意字节差异误报为 hook。后续可通过可信符号、函数边界或受控回溯提升召回。
- API set 和未解析 delay import 先保持未知，不因指向系统 DLL 或名称唯一而宣称全覆盖。

## 后果

测试和正式实现都必须先输出 patch 覆盖和差异，再输出 inline 分类；EAT/IAT 独立汇报，不能互相抵扣。所有“无发现”只能限定到已经成功比较的范围。
