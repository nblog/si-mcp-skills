# ADR 0003：MCP 精确 pin 与分析库最低版本

日期：2026-11-19。状态：已接受；补充 [ADR 0001](0001-python-mcp-skill-and-read-only-boundary.md) 的依赖策略。

## 背景

实测确认 MCP SDK `1.30.0` 可与当前 `simcp.exe` 协议和 Python 导入路径配合。尝试放宽为 `mcp>=1.30.0` 时，依赖解析到 MCP `2.3.0` 后出现不兼容导入路径，入口无法启动。LIEF `1.0.0`、Capstone `5.0.9`、Pydantic `2.12.5` 和 Typer `0.20.0` 是已通过离线与 WXWork E2E 的研究版本，需要作为可回溯下限保留。

## 决策

1. PEP 723 依赖中 MCP 精确声明为 `mcp==1.30.0`。
2. 分析库保留研究验证过的最低兼容版本：`lief>=1.0.0`、`capstone>=5.0.9`、`pydantic>=2.12.5`、`typer>=0.20.0`。
3. 运行时强制实际 MCP 版本为 `1.30.0`，校验四个分析库不低于上述下限，并在报告中记录五个直接依赖的实际解析版本，便于复现。
4. 当后续 System Informer MCP / Python SDK 组合通过 transport、模块枚举、内存读取和 E2E 验收后，新增验收记录并解除或更新该精确 pin；不能仅因上游发布新版本就自动放宽。
5. `simcp.exe` 路径与 SHA-256 仍按 ADR 0001 精确 pin；本决策只涉及 Python 依赖。

## 取舍

MCP 精确 pin 暂时放弃新 SDK 的兼容性修复，但保证当前 Skill 可运行；其余依赖使用最低版本，既保留已验证基线，也允许兼容修复。报告记录实际版本，使依赖差异可以定位。
